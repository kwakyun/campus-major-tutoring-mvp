# 프로젝트 개선 점검 — 2026-09-19

목표: 현재 프로젝트에서 개발이 미흡한 부분을 찾고 개선한다.
기존 게이트 문서의 PASS만으로 완료를 판단하지 않고 현재 소스와 실행 결과를 기준으로 점검한다.

## 수정 및 검증 완료

- API 기본 주소의 불필요한 `/api` 접두사 제거. 생활권 조회 실패 안내와 재시도, 조회 실패와 빈 목록 구분.
- 예약 상세 조회에 참여자 권한 검사 추가. 제3자 조회/결제 및 튜터의 학습자 결제 대행 차단.
- 모의 결제를 `APP_ENV=local`, `PAYMENT_MODE=fake`에 제한. 취소 등 결제 대기가 아닌 예약 상태 변경 차단.
- 협의방 경로와 제안서의 소속 일치 검증, 저장소에서도 실제 당사자·역할 검증.
- 비공개 수업과 비학습자 계정의 협의방 생성 차단.
- 잘못된 제안 시간, 금액, 장소, 수업 길이와 빈/과도하게 긴 메시지 거절. 제안 검증은 이전 버전 변경 전에 수행.

검증:

- API TypeScript 빌드 통과.
- `apps/api`에서 `node ../../node_modules/vitest/vitest.mjs run --no-cache`: 24/24 통과.
- 루트에서 `node node_modules/vitest/vitest.mjs run tests/integration/s05-negotiation-and-booking.spec.ts --no-cache`: 9/9 통과.
- 새 HTTP 회귀 테스트: `apps/api/test/transaction-access.e2e-spec.ts` (13건).
- 기존 빌드 산출물 쓰기 권한 오류는 승인된 권한 확장으로 재빌드하여 해소. 테스트 캐시 쓰기는 비활성화.

## 확인된 미완료 항목

1. `apps/web/src/app/courses/[id]/page.tsx`: 조회 실패 시 임의 샘플 수업을 반환한다. 협의 시작이 실제 협의방 생성 없이 수업 ID로 이동한다.
2. `apps/web/src/app/chat/[id]/page.tsx`: 조회·메시지 전송 실패를 데모 데이터로 대체한다. 실제 성공과 실패 상태를 분리하고 거래 흐름을 검증해야 한다.
3. `apps/web/src/app/chat/[id]/agreement/page.tsx`: 고정 날짜·강사·금액·결제 완료 문구를 표시한다. 실제 예약을 연결하고 캘린더 동작을 구현해야 한다.
4. 수업/교육자 상세의 공유 버튼은 실제 복사 없이 성공 알림만 띄운다. 교육자 상세에는 고정 후기·수업이 있다.
5. 수업 탐색 카테고리 탭은 선택 상태만 바꾸고 필터에 반영되지 않는다. 첫 페이지 이후의 수업 탐색과 검색 범위도 점검해야 한다.
6. `api-client.ts`의 추천 실패 시 클라이언트 계산은 모든 오류를 삼키며, 서버의 필수 조건 검증과 일치하지 않는다.
7. S04 통합 테스트는 최신 기본 빌드 경로 `dist_app` 대신 `dist-build`를 사용한다. 테스트 실행 명령과 현재 산출물의 일치를 정비해야 한다.
8. 주요 저장소는 인메모리이며 실제 DB 영속성과 재시작 복구는 미구현이다. 실제 인증·결제 제공자 연동도 구현되지 않았다.

위 항목은 후속 작업 목록이며 전체 목표 완료를 의미하지 않는다. UI 변경은 실제 브라우저 동작도 검증해야 한다.
