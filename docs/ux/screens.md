# 전공한시간 — 화면 목록·상태·API 연결 (S02-T02)

작성: A3 · 작성일: 2026-09-19

## 1. 진입·탐색

| 화면 | 필요 API | 상태 | 비고 |
|---|---|---|---|
| 홈/진입 | - | - | 대학생용 문구("이번 프로젝트에 필요한 전공 밖 지식")와 편입준비생용 문구("지원 학과의 기초 개념과 질문 정리")를 별도 진입 카드로 분리(사업계획서 8절). 재학 여부를 묻는 필수 질문 없음 |
| 수업 탐색 | `GET /courses` | 로딩/빈결과/정상 | 필터: 주제·생활권·시간 |
| 수업 카드 | `GET /courses` 응답 필드 | - | **시간·결과물·가격을 한 카드에서 함께 표시**(요구사항: 시간 조건을 먼저 반영). askingPrice는 "협의 시작 가격"이라는 보조 문구 병기(최종 청구액 아님) |
| 수업 상세 | `GET /courses/{id}`(신규 필요 — 계약 변경 요청) | 정상/권한오류 없음(공개) | 샘플 설명(sampleDescription)과 확인 상태(verificationBadges)를 **분리된 섹션**으로 표시. "학교 인증됨" 배지 옆에 "교육 능력을 보증하지 않습니다" 보조 문구 |
| 학습 요청 등록 | `POST /learning-requests` | 로딩/검증오류 | 목표·수준(선택)·기한·예산·가능시간 입력 |
| 매칭 결과 없음 | `POST /learning-requests/{id}/waitlist` | 빈결과 | flows.md §5 참고 |

## 2. 협의·예약

| 화면 | 필요 API | 상태 | 비고 |
|---|---|---|---|
| 협의방 | `GET/POST /conversations/{id}/messages` | 로딩/권한오류 | 참여자만 접근 |
| 제안 카드 | `POST /conversations/{id}/proposals` | - | 커리큘럼·시간·장소·인원·**수업료·양측 보증금·수수료·정산예정액**을 각각 별도 라인으로 표시(합산 금액 하나로 뭉치지 않음) |
| 재제안 알림 | - | 오래된 제안 | flows.md §4 |
| 최종 합의서 | `proposals[].terms` | - | 수락 직전 전체 금액 명세 재확인 화면(서버 계산값만 표시, 클라이언트 재계산 금지) |
| 결제 대기 | `GET /bookings/{id}` | 결제확인중 | PAYMENT_PENDING 상태 전용 배지 |
| 내 예약 | `GET /bookings/{id}` | 정상 | 상태값 8종(state-machines.md §1)을 사용자 친화적 문구로 매핑 |

## 3. 완료·후속

| 화면 | 필요 API | 상태 | 비고 |
|---|---|---|---|
| 완료 확인 | `POST /sessions/{id}/completion-confirmations` | - | 미응답 시 "운영자 확인 중" 표시(자동 완료 아님) |
| 학습 목표 응답 | `POST /sessions/{id}/learning-outcomes` | - | 선택 입력, 본인만 조회 가능 안내 |
| 후기 작성 | `POST /bookings/{id}/reviews` | 권한오류(미완료) | 완료된 예약에만 노출 |
| 재예약 | `POST /bookings/{id}/rebooking-requests` | - | "동일 교육자와 이어서" 진입점 |
| 교육 활동 기록(교육자) | `GET /tutors/{id}` 확장 또는 신규 API(계약 변경 요청) | - | 공개 여부는 portfolio_consents 토글에 연동. "포트폴리오"이며 "학점/공인자격 아님" 고지 문구 고정 |

## 4. 교육자 화면

| 화면 | 필요 API | 상태 | 비고 |
|---|---|---|---|
| 프로필 등록 | 신규(자기기재 필드, 계약 변경 요청) | 검증오류 | 학교/전공/경력 자기기재 폼과 별도로 "확인 신청" 버튼(verifications) |
| 커리큘럼 등록 | `POST /tutor/courses` | 검증오류/심사대기 | draft→pending_review→published 진행 상태 표시 |
| 커리큘럼 복제 | `POST /tutor/courses/{id}/versions` | 권한오류 | 타인 커리큘럼 복제 시 버튼 자체를 노출하지 않음 |
| 가능 시간 관리 | `PUT /tutor/availability`(기존 아키텍처 §9) | - | 확정 예약 겹침 시 수정 차단 안내 |
| 정산·활동 기록 | 신규(계약 변경 요청) | - | 정산 예정액과 실제 지급 상태를 분리 표시 |

## 5. 운영자 화면

| 화면 | 필요 API | 상태 | 비고 |
|---|---|---|---|
| 심사함 | verifications 조회/승인/반려 API(신규, 계약 변경 요청) | - | 반려 시 사유 입력 필수(빈 값 제출 차단) |
| 매칭함 | learning_requests/waitlist_entries 조회(신규, 계약 변경 요청) | 빈결과 | 후보 없음일 때 "대기 신청 완료" 표시, 허위 매칭 결과 생성 금지 |
| 대기열(미납/미응답) | `GET /bookings?status=...`(신규 필터, 계약 변경 요청) | - | |
| 분쟁함 | `POST /admin/disputes/{id}/resolve` | - | 증거·사유 입력 후에만 결정 가능 |
| 거래 대사 | settlements/payout_attempts 조회(신규, 계약 변경 요청) | - | |

## 6. 인수 기준 대조

- 수업료·양측 보증금·수수료·정산 예정액을 구분해 표시: §2 제안 카드·최종 합의서에서 충족.
- 빈 매칭의 후속 행동과 학습 전후 흐름 설계: flows.md §5~6.
- 합격·자격·취업 보장 문구 없음: §1 진입 문구, §3 교육 활동 기록 고지 문구에서 명시적으로 배제.
