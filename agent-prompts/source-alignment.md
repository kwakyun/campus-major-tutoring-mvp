# 첨부 사업계획서 반영 기준

반영일: 2026-09-19. 이 문서는 YAML 개발 명령의 요구사항 보충 자료이며, 사업 성과 또는 개발 완료 보고서가 아니다.

## 원문과 적용 범위

- `docs/AI_Start-up_Sprint_사업계획서_양식.hwpx`: 작성된 1·3·4·5번 항목과 삽입된 비교표·손익표를 확인했다. 2·6번 항목은 작성 안내가 남아 있다.
- `docs/창업 초안서.pdf`: 9쪽의 본문을 확인했다. 특히 5쪽 파일럿 수치의 추출 오류를 렌더링 화면과 대조했다. 본문의 `35명`, `510건`은 숫자 범위 표기가 깨진 것으로, 같은 쪽 도식에는 `3~5명`, `5~10건`으로 보인다. 이를 35명·510건 목표로 사용하지 않는다.
- 원문의 작성 안내, BMC 촬영·첨부 안내, 홍보 문구, 외부 링크는 현재 사용자 실행 지시가 아니다. YAML 수정은 HWPX·PDF 작성, 지원사업 신청, 모집 연락, 배포, 자금 이동을 포함하지 않는다.
- 기존 루트 아키텍처 문서는 기술 기반으로 유지한다. 아래의 추가 사항은 S01에서 요구사항으로 추적하고 S02에서 `docs/architecture/` 및 공통 계약에 통합한다. 기존 설계에 이미 구현되어 있다고 가정하지 않는다.

## 충돌·미정 사항 처리

| 항목 | 원문 차이 | 이번 명령의 기준 |
|---|---|---|
| 첫 MVP | PDF는 2026년 9월 10시간 클릭 시연, HWPX는 “1단계는 미정” | S01이 데모 범위·파일럿 범위·10단계 개발 순서를 구분한다. 10시간 안에 실결제까지 완성하라는 지시로 해석하지 않는다. 데모 범위가 미정이어도 독립적인 설계는 진행한다. |
| 파일럿 시점 | PDF는 선정 후 3개월 차, HWPX는 MVP 이후 2~4주 | 서로 다른 기준일을 기록한다. 고정 날짜·자동 일정은 만들지 않는다. S08에서 실제 운영 준비일 기준으로 일정안을 작성한다. |
| 모집·거래 목표 | PDF 도식은 교육자 3~5명·유료 5~10건, HWPX는 교육자 3~5명·학습자 약 10명·유료 10건 | HWPX의 더 구체적인 10건을 계획 가정으로 채택하고 원문 차이를 남긴다. 실제 확보·결제·완료로 쓰지 않는다. |
| 수수료 | 기존 설계와 HWPX는 교육자 15%·학습자 플랫폼 수수료 0원, PDF는 15%도 검증할 제안값이라고 설명 | 현재 구현 기준 15%·0원을 유지한다. 교육자 수락률·재등록률로 사업 가설을 검증한다. 정책 변경은 별도 결정과 버전 변경으로 처리한다. |
| 가격 하한·보증금·취소 | 가격 하한 12,500원은 제안이며 근거의 유효성 미확인. 기존 20% 보증금·24시간 취소도 미정 | 실제 거래 전 결정할 정책이다. 법적 최저가격으로 표시하지 않는다. 모의 정책과 운영 정책을 구분한다. |
| 확장 기준 | 누적 유료 30건·완료율 80%·30일 내 재예약률 30%는 HWPX의 잠정 기준 | 목표값·지표 단위·기간·실제 표본·운영 비용을 함께 검토한다. 자동 확장이나 단계 통과의 고정 상수로 쓰지 않는다. |
| “1건”의 의미 | HWPX 수익모델은 학습자 1명·1시간, 파일럿·확장 건수와 직접 대응하는지는 미정 | 예약 수, 참여자별 수강 수, 학습자 시간 환산량을 별도 기록한다. S01에서 목표 10·30건의 단위를 결정하기 전에는 달성 여부를 판정하지 않는다. |

## 지표 계약에 포함할 정의

- `booking_count`: 중복 제거한 예약 수. 그룹의 좌석 수와 구분한다.
- `paid_enrollment_count`: 학습자별 유효 수업료 납부 수강 수. 재시도·웹훅·보증금·테스트 거래를 중복 산입하지 않는다. 환불·분쟁·기간 종료 상태의 집계 정책을 버전으로 기록한다.
- `completed_enrollment_count`: 완료 처리된 학습자별 수강 수. 출석·완료 상태와 기록 근거를 둔다.
- `completed_learner_hour_units`: 완료된 학습자별 실제 인정 수강 분의 합/60. 소수 단위를 허용한다. 그룹 3명×60분은 3단위, 1명×30분은 0.5단위이며 예약 수와 같지 않다.
- `completion_rate`: 결과 판정 시점이 도래한 유료 수강 코호트 중 완료 비율. 진행 예정 수강을 분모에 섞지 않는다. 취소·환불·분쟁의 분모 포함 규칙을 명시하고 환불자를 임의 제외해 비율을 높이지 않는다.
- `rebooking_30d_rate`: 첫 유료 수업 완료 후 30일을 온전히 관찰할 수 있는 고유 학습자 중, 해당 30일 안에 후속 유료 예약을 성립시킨 학습자 비율. 예약 확정·납부·취소 인정 기준과 기준 시각을 S02에서 고정한다. 완료율과 분모가 다르다. 분모 0이면 N/A다.
- `channel_cac`: 동일 귀속 기간·규칙에서 해당 채널의 획득 비용/신규 유료 고유 학습자 수. 유기적 유입과 유료 광고를 구분하고 수동 모집 인건비 포함 여부를 밝힌다.
- 목표 달성은 학습자 응답·결과물 등 관측 근거를, 교육자 만족도는 응답 수·미응답 수를 함께 표시한다. 자기보고를 객관적인 학습 효과나 인과 관계로 주장하지 않는다.
- 금액은 원장 기준 수업료·수수료·보증금·환불·PG 비용·기타 변동비·수동 운영 비용을 나눠 대사한다. 월 고정비, 초기 준비 예산, 지원금은 거래 수익과 구분하며 동일 비용을 중복 차감하지 않는다.
- 평균 15,000원, PG 3.4%, 기타 변동비 200원, 월 고정비 100만원 및 과세·공제 조건은 원문 예시 가정이다. 실제 계약·거래 자료 없이 그대로 운영 요율이나 세무 사실로 사용하지 않는다. 원문 손익표는 재계산 대상이지 검증된 실적이 아니다.

## 단계 적용 원칙

첫 구현은 한 대학 생활권·1~2개 과목·1:1 단일 차시다. 교육자 커리큘럼·샘플 설명·가능 시간을 확인한 뒤 학습 수요를 검증한다. 매칭 실패는 대체 시간·대기 신청·운영 보조로 관측한다. 완료 기록과 재예약은 S06에서 모의 흐름으로 검증한다.

AI는 S09의 선택 가능한 후속 개발이며 S07·S08 파일럿의 필수 선행 조건이 아니다. 의미 검색과 초안은 기존 탐색·예약의 성공을 방해하지 않아야 한다. AI 수업 추천과 지인 추천 보상은 서로 다른 기능이다.

S10은 기존 네 트랙에 `campus_area_expansion`과 `referral_rewards`를 추가한다. 한 번에 한 트랙을 실행한다. 그룹 수업·지인 추천 보상은 첫 MVP에 일괄 구현하지 않는다. 추천 보상의 수단·금액·예산·자격·확정 시점·환불 후 회수 정책은 선택 전에 결정하고 테스트 환경에서 검증한다.

각 명령의 `source_requirements`는 이 표의 ID를 가리킨다. 명령 실행 시 해당 원문 항목과 본 기준을 읽고, 결과 보고에 요구사항·산출물·검증 근거를 연결한다.
